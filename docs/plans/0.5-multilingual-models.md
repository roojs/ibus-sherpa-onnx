## Purpose

- **🔷** Preferences: **Language** first, then a **model list filtered by that language**.
- **🔷** Close / apply: download + extract (cache) → polkit move → user `model` symlink → ensure GNOME input source → **`ibus restart`** (same finish path as 0.4).
- **🔷** Dictation language matches the choice: English-only pack for `en`, or multilingual Nemotron-3.5 + per-stream language hint for other locales / `auto`.
- **🔷** Keep one KeyFile (`settings.ini`); no path env vars; polkit still **never** downloads.

## Background (upstream)

Today we ship catalog entries for **English-only** Nemotron:

- `sherpa-onnx-nemotron-speech-streaming-en-0.6b-{560,1120}ms-int8-2026-04-25`

Upstream also publishes **multilingual** Nemotron-3.5 streaming (≈40 language-locales, OpenMDW), e.g.:

- `sherpa-onnx-nemotron-3.5-asr-streaming-0.6b-{560,1120}ms-int8-2026-06-11`

Language is a **per-stream** option (`OnlineStreamSetOption(stream, "language", "ja")`). Empty / `auto` = detect. English-only packages **ignore** the option.

Requires a **libsherpa-onnx** new enough for multilingual Nemotron (prompt_index / stream language API). Gate 0.5 on a known runtime version; bump `Depends` / README accordingly.

IBus component today:

```xml
<language>en</language>
<layout>us</layout>
```

That only controls **Settings grouping / keyboard layout**, not ASR. Changing spoken language without changing models is misleading — do not add a decorative language combo alone.

## Desired UX

1. Open Preferences.
2. Choose **Language** (e.g. English, Japanese, …, Auto).
3. **Select model** list updates (chunk sizes / pack family available for that language; **installed** / **needs downloading** as today).
4. Close → pipeline runs → GNOME has Sherpa → IBus restarted → dictate in that language.

Default language: **English** (current behaviour). Default model selection: **None** until the user picks (unchanged).

## Design choices

### Catalog shape

Extend [`Models.vala`](../../src/Models.vala) from parallel arrays to a small structured catalog, e.g. entries with:

| Field | Role |
| --- | --- |
| `id` / `names[]` | Archive / dir basename |
| `family` | `nemotron-en` \| `nemotron-3.5-ml` |
| `chunks[]` / `sizes[]` / `archive_bytes[]` | As today (still **560** / **1120** only) |
| `languages[]` | Locales this pack can serve (`en` only for en pack; full list or `*` for multilingual) |
| `checksum` | Packaged `data/checksums/<dir>.sha256` |

Prefs:

- **Language** row → writes `general/language=` in `settings.ini` (BCP-47-ish short codes: `en`, `ja`, `auto`, …).
- **Select model** → only entries whose `languages` include the selection (treat `auto` as multilingual family only).

**English:** prefer offering the existing **en-0.6b** packs (smaller / known-good). Optionally also list multilingual packs with hint `en` (**💩** — defer if UI clutter).

**Other locales / Auto:** multilingual 3.5 packs only; engine sets stream language from prefs.

### Runtime (Transcriber)

- After creating the online stream (and on each reset if required by the API), call stream **language** option when the active tree is multilingual.
- English-only tree: do not require the option.
- Detect multilingual via catalog `family` (or encoder metadata later) — **🚫** do not guess from directory name alone without a catalog field.
- May need Vala vapi + `libsherpa-onnx` bump for `OnlineStreamSetOption` (or equivalent).

### GNOME / IBus language presentation

Two layers — keep them honest:

| Layer | What it means |
| --- | --- |
| ASR language | Prefs `language` + model family + stream option |
| Settings grouping | Component `<language>` / `<layout>` (and which engine id is in `input-sources`) |

**Recommended for 0.5:**

1. **Phase A (ASR + prefs catalog)** — Language + filtered models + download/install + stream hint. Keep a **single** engine id `sherpa-onnx` in gsettings (0.4 `ensure_input_source`). Accept that GNOME may still group the IME under English until Phase B.
2. **Phase B (Settings grouping)** — Map prefs language → IBus `<language>` + `<layout>` so Settings shows the IME under the right language:
   - **Option B1 (preferred):** multiple `<engine>` entries in `sherpa-onnx.xml` sharing the same binary (`sherpa-onnx-en`, `sherpa-onnx-ja`, …) with fixed language/layout; prefs switches the gsettings source to the matching engine name (still one process pattern via factory).
   - **Option B2:** single engine; only update longname/description; grouping stays weak.

**🚫** Do not rewrite system component XML from prefs. **🚫** Do not invent a second parallel IME package per language.

Layout map (starter; expand with catalog): `en`→`us`, `ja`→`jp`, `de`→`de`, …; `auto`→keep `us` or last explicit layout (**💩** decide in implement).

### Install / finish path

Reuse 0.4 finish:

1. User download + libarchive extract → `~/.cache/ibus-sherpa-onnx/download/`.
2. `pkexec` install-model (allowlist **must** grow for new dir names).
3. User `model` symlink → system tree.
4. `ensure_input_source` (engine id from Phase B map if multi-engine).
5. `ibus restart` + close.

CLI: extend `cli-fetch-nemotron-model.sh` with language + chunk, or `--list` / args mirroring prefs (**⏳** after prefs path works).

### Config

```ini
[general]
hotkey=Ctrl+Shift+Space
notifications=false
preedit-animation=true
language=en
```

Active weights remain the **`model` symlink** (not a path in the ini). Language is orthogonal so switching language can imply a different default model / require re-pick if the current symlink’s family does not support the new language (clear selection to None or prompt — prefer **auto-clear model radio to None** when language change invalidates current symlink).

## Explicit non-goals

- **🚫** Decorative language prefs that do not change model / stream behaviour
- **🚫** Shipping multilingual weights inside the `.deb`
- **🚫** Polkit / root network download
- **🚫** Per-language parallel user `models/` trees (system store + one user symlink still)
- **🚫** Offering 80/160 ms chunks again
- **🚫** Full 40-locale UI polish in the first cut — start with a **short curated list** + Auto (expand from encoder `prompt_dictionary` later)
- **🚫** Changing the user’s session from the agent without ask
