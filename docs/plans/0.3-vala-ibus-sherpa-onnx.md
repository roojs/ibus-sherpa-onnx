## Agent rule: do not change the user’s system/session

**🚫 CRITICAL — read every time before running shell commands.**

Do **not** mutate the user’s desktop session or machine without an **explicit** ask in the current message. That includes (non-exhaustive):

- `gsettings` / `dconf` (input sources, shortcuts, anything)
- `ibus engine …`, `ibus restart`, switching IMEs
- starting/stopping/killing `ibus-engine-sherpa-onnx`, `ibus-daemon`, or other session processes
- `sudo`, `apt`, `meson install`, writing under `/usr`, `~/.config/ibus`, etc.
- adding input sources, grabbing Super+Space behaviour, “helpful” session tweaks

**Allowed without asking:** repo edits, `meson`/`ninja` **build** in this project tree, read-only inspection (`gsettings get`, `ibus engine` with no set, `pgrep`, reading files).

**When a session/install step is needed:** print the exact command(s), explain why, and **wait** for the user to run them (or to say “go ahead and run X”). Do not “just try it” on the live session.

**Why:** Phase 1 runtime registration is easy to “fix” by poking GNOME/IBus; that left the session in a confusing state. User must stay in control.

## Purpose

- **🔷** Convert the PoC into a real **IBus input-method engine** (daemon process), so dictation lands in **whatever text field has focus** — not a hacked GTK composer, not AT-SPI / ydotool injection.
- **🔷** Reuse [`src/transcriber.vala`](../../src/transcriber.vala): GStreamer mic → sherpa-onnx Nemotron; `partial` / `endpoint` already Idle-marshalled to the main loop.
- **🔷** Map `partial` → `IBus.Engine.update_preedit_text`; `endpoint` → `commit_text` (then keep listening until stop).
- **🔷** Activation: engine idle (mic off) until an explicit **toggle hotkey**; do **not** open the mic merely because the Speech IME is selected.
- **🔷** **One hotkey toggles listen on/off** (press again to stop). No Escape-to-stop, no “typing stops dictation.”
- **🔷** Hotkey **remappable** via a small config file (not environment variables — hostile UX). Default `Ctrl+Shift+Space`.
- **🔷** Keep CLI `sherpa-onnx-mic` for recognizer smoke tests.
- **💩** Park GTK composer under `src/gtk/` as a sideline demo (`sherpa-onnx-gtk`); not the main integration story.

## How IBus activation works

IBus is a **system input-method bus**, not “run a daemon and inject keys.”

```
  [Focused app] → toolkit IBus client → ibus-daemon → ibus-engine-sherpa-onnx
       ↑                                                      │
       └──── preedit / committed text ←───────────────────────┘
```

1. **`ibus-daemon` must be running** (desktop session usually starts it).
2. User **selects** our engine in the IBus panel (e.g. “Sherpa ONNX”) — same as switching to Pinyin. That makes us the **active IME**.
3. When a text field has focus, key events go to our engine (`process_key_event`).
4. We show **preedit** (`update_preedit_text`) and **commit** (`commit_text`) into that focused widget.
5. ibus-daemon **spawns** our process from the component XML `<exec>` when needed.

### Why not “always listen while IME selected”

Selecting the Speech IME only means we receive keys when a text field is focused. It does **not** mean “open the mic.” Auto-listening on enable/focus would be surprising, privacy-hostile, and wasteful. Mic stays off until the start hotkey.

### Toggle hotkey (start and stop)

- **Behaviour:** the same accelerator **toggles** listening. First press → `start()`; second press → `stop()`, hide/cancel preedit (commit any pending partial only if we already have an endpoint policy — PoC: discard unfinished preedit on stop).
- **Default:** `Ctrl+Shift+Space` (matches 0.2).
- **Config (no env vars):** read `~/.config/ibus-sherpa-onnx/hotkey` (one accelerator line, e.g. `Ctrl+Shift+Space`). Missing/empty → default. Document in README how to edit that file.
- **🚫** Do not use `STT_*` environment variables for the hotkey (or other user-facing settings in this slice).
- **While listening:** other keys **pass through** (`return false`) so normal typing still works; only the toggle key is consumed.
- **Later (not this slice):** ibus-setup / GSettings prefs UI instead of hand-editing the file.
- **Constraint:** hotkey only arrives when **this IME is active** and a client is focused. Global shortcuts with another IME selected are out of scope.

## Phase 3 — Debian package = register / unregister

**Why:** Runtime `register_component` from a hand-launched binary does **not** show up in GNOME’s input sources. Real IBus engines (e.g. `ibus-pinyin`) register by **shipping files**; `ibus-daemon` discovers them and **spawns** the engine when needed. A `.deb` install/remove is that lifecycle — not clever maintainer scripts.

### How registration works (no clever postinst)

Same pattern as `ibus-pinyin`:

| Install path | Role |
| --- | --- |
| `/usr/share/ibus/component/sherpa-onnx.xml` | Declares the engine; `<exec>/usr/libexec/ibus-engine-sherpa-onnx --ibus</exec>` |
| `/usr/libexec/ibus-engine-sherpa-onnx` | Engine binary (our `ibus-engine-sherpa-onnx`, renamed on install) |

- **Install package** → those files appear → after a normal session IBus reload/restart (user may run `ibus restart` once, or log out/in), **Sherpa ONNX** shows in GNOME input sources. Daemon starts the binary with `--ibus` when the IME is used.
- **Remove package** → dpkg deletes those files → engine disappears. No postrm “unregister” API needed.
- **🚫** No postinst that runs the engine, calls `ibus engine …`, edits gsettings, or downloads models.
- **🚫** No relying on runtime `register_component` for the packaged product path (keep it only as an optional unpackaged dev aid, or drop it when `--ibus` is implemented).

### Engine binary changes for packaging

- **🔷** `⏳` Support **`--ibus`**: when ibus-daemon spawns us, set up `Factory` + `request_name` and **do not** call `register_component` (daemon already knows us from the XML). Match upstream engine mains / pinyin’s `--ibus` exec line.
- **🔷** `⏳` Model still **not** in the `.deb` (~hundreds of MB). User keeps `~/.config/ibus-sherpa-onnx/model` as a directory or symlink (document in README). Package `Depends:` on `ibus`, `libsherpa-onnx-c-api1`, GStreamer runtime bits, etc.

### Packaging deliverables

- **🔷** `⏳` `data/sherpa-onnx.xml` (component; exec → `/usr/libexec/ibus-engine-sherpa-onnx --ibus`).
- **🔷** `⏳` Meson `install: true` for the engine binary to `libexec` with the packaged name (or `debian/*.install` rename).
- **🔷** `⏳` `debian/` package (e.g. `ibus-sherpa-onnx` or `ibus-sherpa-onnx`): `control`, `rules`, `changelog`, `copyright`, `.install` for binary + XML. Build with normal `dpkg-buildpackage` / whatever this repo already uses for sherpa.
- **🔷** `⏳` README: build `.deb`, `sudo apt install ./…deb`, symlink model, `ibus restart` (user runs), add Sherpa ONNX in Settings → Keyboard, toggle hotkey / `~/.config/ibus-sherpa-onnx/hotkey`. Uninstall: `sudo apt remove …`.
- **💩** Keep `sherpa-onnx-mic` / `sherpa-onnx-gtk` out of that binary package (or separate packages later).

### Phase 3 success

- **🔷** `⏳` User installs the `.deb` → engine listed in GNOME / `ibus list-engine` after IBus reload → select Sherpa ONNX → toggle → dictate. Remove `.deb` → engine gone from the list.
