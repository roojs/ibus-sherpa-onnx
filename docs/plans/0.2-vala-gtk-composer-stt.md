## Purpose

- **🔷** Stage-2 PoC: prove STT fills a **first-party GTK** composer — not AT-SPI / “inject into whatever has focus” (Whisper-ss style desktop injection).
- **🔷** Hello-world window with the **growing** OLLMchat composer pattern (single `TextView`; grows past one visual line).
- **🔷** **Microphone** on the **right**; click **starts** listening (does not stop).
- **🔷** **Ctrl+Shift+Space** also **starts** listening (same as mic).
- **🔷** **Stop** listening via **Escape** or **keyboard typing** into the composer (hello-world stop paths).
- **🔷** Engine exposes **`start()`** and **`stop()`** separately so a later UI can add its own Stop button without changing the engine.
- **🔷** Mic icon **hides when listening starts**; returns when stopped.
- **🔷** While listening and waiting for speech: **spinner** (or similar) in the **text area** — listening feedback, not a model-load wait.
- **🔷** Recognizer / model load at **engine construct / app startup**; after that `start()` only opens the mic pipeline — already ready to decode.
- **🔷** Live transcript **writes into the GTK text buffer** (partials update; endpoint commits like today’s stdout newline).
- **🔷** **Threading:** audio / decode stay on the **background** (GStreamer streaming thread); **only** `GLib.Idle.add` touches GTK (buffer, widgets, CSS).
- **🔷** Reuse Phase 0.1 stack: GStreamer mic → sherpa-onnx online transducer (Nemotron).
- **ℹ️** Path into OLLMchat later: same UX surface as `ChatInput` (mic beside / instead of play), not a separate desktop daemon.
- **💩** `⏳` Keep CLI `stt-poc` binary working (extract shared engine; GTK is a second executable).

## Design notes (review)

### Threading (required)

- **🔷** GStreamer `appsink` `new_sample` runs on a **streaming / worker thread**, not the GTK main loop.
- **🔷** On that thread the engine may:
  - map the buffer → `float[]`
  - `accept_waveform` / `is_ready` / `decode` / `get_result` / `is_endpoint` / `reset`
  - copy out plain `string` results (no GTK, no widget pointers)
- **🔷** Marshal to the main loop with **`GLib.Idle.add`** before any UI side effect:
  - emit `partial` / `endpoint` **from the idle callback**, **or**
  - idle callback directly updates the composer (if the engine owns the UI hook)
- **🔷** GTK rules: `Gtk.TextBuffer`, `ComposerInput`, buttons, CSS classes, focus — **main loop only**.
- **🔷** `start()` / `stop()` / shortcut / mic click / Escape / key handlers run on the main loop; they only flip pipeline state and listening chrome.
- **💩** Coalesce partials: if several decodes queue before the idle runs, idle publishes the **latest** partial only (drop stale `\r`-style updates).
- **ℹ️** 0.1 CLI printed from the worker thread (acceptable for stdout). GTK **must not** do that.

```
  [GStreamer streaming thread]              [GTK main loop]
  new_sample
    → accept_waveform / decode
    → text changed?
         │
         └─ Idle.add(text copy) ──────────► update TextBuffer
                                            (partial or endpoint commit)
```

### Why in-GTK (not desktop injection)

- **🔷** Injecting keystrokes / AT-SPI into arbitrary GTK widgets is brittle (focus, IME, Android, Wayland).
- **🔷** This PoC owns the `Gtk.TextBuffer` — updates are normal Vala/`buffer.insert` / `update_entry` on the main loop.

### Composer yank (not `libollmchatgtk` link)

- **🔷** Copy the grow behaviour from OLLMchat:
  - [`ScrolledView.vala`](/home/alan/gitlive/OLLMchat/libollmchatgtk/ScrolledView.vala)
  - [`ChatInput.vala`](/home/alan/gitlive/OLLMchat/libollmchatgtk/ChatInput.vala)
- **💩** Do **not** `dependency('ollmchatgtk')` for this PoC — pulls Adwaita app stack, markdown, etc.
- **💩** Namespace in PoC: `SttPoc` (drop `OLLMchatGtk`).
- **💩** Slim `ChatInput` → `ComposerInput`:
  - Keep: `ScrolledView` + `TextView` + placeholder + `lines_changed` expand chrome.
  - Replace side **play** with side **mic** (`audio-input-microphone-symbolic`).
  - Mic visible when **idle** (including multi-line); **hidden while listening**.
  - Drop `send_clicked` / Ctrl+Enter send (not needed for STT hello world).
  - Keep `text()` / `update_entry()` for STT writes.
- **ℹ️** OLLMchat behaviour reference: [`1.30-chat-input-composer.md`](/home/alan/gitlive/OLLMchat/docs/plans/1.30-chat-input-composer.md) — one TextView grows; **no** Entry↔TextView flip.

### Listening UX

- **🔷** Idle: mic visible on the right; placeholder like “Speak or type…”.
- **🔷** **Start** only: mic click **or** **Ctrl+Shift+Space** → `engine.start()`; hide mic.
- **🔷** **Stop** (hello world): **Escape** **or** any **keyboard character** typed into the composer → `engine.stop()`; show mic again.
- **🔷** Engine API is **`start()`** / **`stop()`** (not a single toggle) so OLLMchat can later wire a dedicated Stop button to `stop()` without changing this PoC contract.
- **🔷** While listening with **no transcript yet**: show a **spinner in the text area** (overlay next to / instead of the idle placeholder) — “waiting for you to talk”.
- **💩** Hide the spinner on first non-empty `partial` (text takes over); show again after an endpoint if still listening and the next utterance has not started.
- **ℹ️** Readiness: Nemotron / `OnlineRecognizer` create is the **slow** bit — do it in **`SttEngine` construct** (same as 0.1 before “Listening…”). Mic `start()` only sets the GStreamer pipeline to `PLAYING`. No post-click “warming up” state for the model.
- **💩** Partials: rewrite the **current utterance** region in the buffer (same idea as stdout `\r` overwrite).
- **💩** Endpoint: commit utterance into the buffer (trailing space or newline), reset sherpa stream, **keep listening** until Escape / typing / explicit `stop()`.

### Window chrome

- **💩** `Adw.Application` + `Adw.ApplicationWindow` (matches OLLMchat stack; dep already common).
- **💩** Minimal layout: header bar title “STT PoC” + centered composer strip (not a full chat view).
- **🔷** Shortcut: application-level `<Control><Shift>space` → **start** listen (idempotent if already listening).
- **🔷** Escape / TextView key controller → **stop** when listening.

## Phase 2 — Extract STT engine from CLI

**Why:** GTK and stdout PoCs share recognizer + GStreamer path; avoid duplicating `main.vala`.

### 2.1 Shared engine

- **🔷** `✔️` New `src/stt_engine.vala`: owns
  - online recognizer create (same config as today’s `main.vala`)
  - GStreamer pipeline start/stop
  - signals: `partial(string text)`, `endpoint(string text)`
- **🔷** `✔️` **Engine owns the thread boundary:** `new_sample` does decode on the worker thread; **never** emits `partial`/`endpoint` from that thread — always `GLib.Idle.add` then emit.
- **🔷** `✔️` Handlers (CLI stdout **and** GTK buffer) may assume they run on the **main loop**.
- **🔷** `✔️` Refactor `src/main.vala` CLI to use the engine (stdout behaviour unchanged, but prints move onto Idle like GTK).
- **💩** Model dir / `--stats` stay CLI flags; GTK binary takes the same optional model-dir argv.

### Phase 2 code proposals

### 1. `src/stt_engine.vala` — new (sketch)

```vala
namespace SttPoc {
	public class SttEngine : GLib.Object {
		public signal void partial(string text);
		public signal void endpoint(string text);
		public bool listening { get; private set; }

		public SttEngine(string model_dir) {
			/* Create OnlineRecognizer here (slow / startup). After this, start() is ready. */
		}
		public void start() { /* pipeline PLAYING only — call from main loop */ }
		public void stop() { /* pipeline NULL + reset — call from main loop */ }

		/* Inside new_sample (worker thread): decode only; then: */
		/*   var copy = result.text; */
		/*   GLib.Idle.add(() => { this.partial(copy); return false; }); */
		/* Endpoint same pattern with this.endpoint(copy) then reset stream. */
	}
}
```

### Phase 2 success

- **🔷** `✔️` `./build/stt-poc` still streams to stdout.
- **🔷** `✔️` Engine can start/stop without destroying the process.
- **🔷** `✔️` No `partial`/`endpoint` emission from the GStreamer thread (Idle only).

### 2. `src/gtk_main.vala` — start / stop + fill (sketch)

```vala
void start_listen(ComposerInput input, SttEngine engine) {
	if (engine.listening) {
		return;
	}
	engine.start();
	input.set_listening(true); /* hides mic, shows spinner */
}

void stop_listen(ComposerInput input, SttEngine engine) {
	if (!engine.listening) {
		return;
	}
	engine.stop();
	input.set_listening(false); /* shows mic */
}

/* mic_clicked / <Control><Shift>space → start_listen */
/* Escape or TextView key_pressed while listening → stop_listen */
/* engine.partial / endpoint → update buffer (signals already Idle-marshalled) */
```
