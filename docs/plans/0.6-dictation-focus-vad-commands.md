## Purpose

- **🔷** Keep hands-free dictation alive across **neutral window switches** (e.g. glance at a browser / test app) instead of treating every iBus `reset` as “stop the mic.”
- **🔷** Prefer a **smart focus policy** (only halt when focus moves to another text-editable / iBus-focusable target). Hotkey **“Block Resets”** is the fallback if iBus cannot distinguish those cases cleanly.
- **🔷** Configurable **silence paragraph breaks** (`\n\n` after a medium pause) — a handy way to split paragraphs without saying a command.
- **🔷** Configurable **silence auto-stop** (default: never) — a handy way to end listening after a long quiet stretch instead of leaving the mic open forever.
- **🔷** **Zero-latency voice commands** on the live token stream: spoken paragraph break + configurable stop phrase — no extra buffering before commit.
- **🔷** **App-triggered start/stop** over session **D-Bus** so a host app can put a microphone button on its UI (focus its text field, then `Start` / `Stop`).
- **🔷** Preferences **Test Area** so silence timings and spoken commands can be tuned without hopping between apps.

## Problems to close

| Issue | Notes |
| --- | --- |
| Window switch kills dictation | [`Engine.reset`](../../src/Engine.vala) stops listening whenever the client (or iBus) emits `reset`. Multi-window workflows break. |
| No silence paragraph break | Natural pauses do not insert `\n\n`; only ASR endpoint → commit as continuous prose (or say a command / press Enter). |
| Mic stays open until explicit stop | Listening runs until hotkey / typing / reset. Optional long-silence auto-stop would be a convenient hands-free end. |
| Stop / new paragraph only via hotkey / typing | No spoken stop or spoken paragraph command on the decode stream. |
| Apps cannot drive the mic | No public API for a host app mic button; only IME hotkey / panel property. |
| Tuning silence needs external apps | Prefs has hotkey / notify / animation / models only — no sandbox text view. |

## Current behaviour (baseline)

```
focus_in  → reload Config + ensure Transcriber
reset     → if listening: update_listening(false)   ← the breakage
endpoint  → commit_text (Transcriber uses online
            recognizer enable_endpoint + rule1/rule2
            trailing silence; not a separate Silero VAD)
```

- [`src/Transcriber.vala`](../../src/Transcriber.vala) — `rule1_min_trailing_silence` / `rule2_min_trailing_silence` endpoint gates; mic on/off; `partial` / `endpoint` Idle signals.

## Desired UX

1. Start listening (toggle hotkey). Dictate into an editor.
2. Alt-Tab to a **non-editable** window (docs, browser content, another monitor). Mic **keeps** listening; later focus back and text continues to land (or lands into the newly focused editable if policy says so — see Design).
3. Click into a **different text field** → dictation **stops** (or follows a documented policy) so the previous field is not left “open.”
4. Natural pause past the paragraph slider → next phrase starts a new paragraph (`\n\n`) without a voice command.
5. Optional long silence past the auto-stop slider → mic off, so you need not leave listening open forever (default = disabled / never).
6. Say **“new paragraph”** / **“line break”** → `\n\n` committed immediately.
7. Say the configured stop phrase → mic off immediately.
8. In a cooperating app: focus the text field → D-Bus **Start** (mic on) → speak → D-Bus **Stop** (commit leftover partial, mic off).
9. Open Preferences → Test Area: speak, see output, tweak sliders/phrases without leaving the dialog.

## Design choices

### Focus / reset policy (Primary)

**Goal:** Distinguish “neutral focus change” from “user moved to another input context.”

**Investigation first (Phase A):** Log `focus_in`, `focus_out`, `reset`, `enable`, `disable` (and any useful iBus context: `has_focus`, surrounding text capability, client name if available) while:

1. Alt-Tab between editor and a non-IME window.
2. Click from editor into another Gtk/Qt text entry.
3. Submit / clear in apps that call `Gtk.IMContext.reset` (terminal Enter, some dialogs).

**Target policy (if signals allow):**

| Event pattern | While listening |
| --- | --- |
| Neutral window switch (no new editable focus) | **Keep** listening; do **not** treat `reset` as stop |
| Focus enters another text-editable / iBus client | **Stop** listening (commit unfinished partial first, same as typing interrupt) |
| Explicit client reset that means “input context torn down” while still our focus | **💩** decide from logs — may still need to stop to avoid ghost preedit |

**Hard constraint:** Do not break apps that rely on `reset` after submit (VTE Enter, etc.). Those must still clear preedit / not leave the mic stuck if the context is gone.

**Commit target while “floating”:** Prefer keeping the **last focused editable** as the commit destination only if iBus still allows commits without `has_focus`; otherwise buffer is wrong. Phase A must prove whether commits succeed after focus_out. If not, “continue listening” may mean **keep the mic + ASR warm** and only `commit_text` again after the next `focus_in` (partials held or discarded — pick one and document).

### Block Resets mode (Secondary / fallback)

If primary policy cannot be made reliable:

- Prefs switch + optional dedicated hotkey: **Block Resets**.
- When on: `Engine.reset` does **not** call `update_listening(false)` (still clear/ignore stale preedit as needed).
- Default **off**. User opts in for multi-window soak sessions.
- Panel / notification cue when Block Resets is active (**💩** symbol vs notify — keep light).

### Silence timers (dual)

One silence clock (contiguous non-speech), two thresholds:

| Timer | Pref key (proposed) | Range | Default | Action |
| --- | --- | --- | --- | --- |
| **A — paragraph** | `silence-paragraph-secs` | `1.5` … `5.0` (or `0` = off) | **off** or a mild default — **💩** pick in Phase B; prefer **off** until soak proves value | Before next phrase commit, inject `\n\n` (handy paragraph split without a command) |
| **B — auto-stop** | `silence-autostop-secs` | `0` … `60` | **`0` = never** | `update_listening(false)` (handy end so the mic is not left open forever) |

Reset the silence clock on speech evidence (`partial` text change and/or endpoint / VAD speech frame).

**🚫** Do not conflate Timer A/B with sherpa `rule1`/`rule2` endpoint lengths without measuring — endpoint already segments utterances; paragraph break is a **formatting** convenience between utterances; auto-stop is an optional **session end** convenience. Neither exists to fix a “is the mic dead?” UX confusion.

### Voice commands (direct stream)

Match on the **live hypothesis / endpoint text** (normalized: case-fold, collapse whitespace). No deferral buffer beyond what ASR already emits.

| Command | Match | Action |
| --- | --- | --- |
| New paragraph | `new paragraph`, `line break` (fixed list v1) | Strip the trigger phrase from committed text; `commit_text("\n\n")` (or append after stripping) |
| Stop dictation | `general/stop-phrase` (default e.g. `stop dictation`) | Strip phrase; stop listening; release session UI |

**Design rules:**

- Prefer match on **endpoint** (stable) first; allow **partial** match for stop if latency matters and false positives are rare.
- Strip the command tokens so they are not left in the document.
- Visible partials that briefly show the command words are **acceptable** (spec).
- **🚫** No LLM / fuzzy semantic matcher in v1 — substring / simple phrase match only.
- Stop phrase empty in prefs → feature disabled.

### Preferences Test Area

- New group (or bottom section): **Test Area** — multiline `Gtk.TextView` (or `Gtk.Text` in a scrolled window).
- Purpose: exercise silence paragraph, auto-stop, and voice commands with immediate visible output.
- **Preferred implementation:** in-process `Transcriber` inside `ibus-setup-sherpa-onnx` writing into the TextView (same model symlink / language as engine). Avoids depending on the live IBus focus/reset path while tuning timers — and still works if Sherpa is not the session IME.
- **Also:** document that full focus-policy testing remains a **multi-window session** soak (Phase A/E), not something the sandbox can fully replace.
- Sandbox Start/Stop button (and/or same toggle hotkey while prefs focused). Reuse listening feedback lightly (button label / spinner).

### Config

Extend `settings.ini` `[general]` (same KeyFile; engine reloads on `focus_in` as today):

```ini
[general]
hotkey=Ctrl+Shift+Space
notifications=false
preedit-animation=true
language=en
# 0.6
block-resets=false
silence-paragraph-secs=0
silence-autostop-secs=0
stop-phrase=stop dictation
```

**💩** Exact key names can match existing Row* conventions (`RowSwitch` / new slider row). Use `0` for disabled on both silence sliders.

### App D-Bus start / stop

Let cooperating apps own a **microphone button** without becoming an IME themselves. Text still lands through normal iBus commit into whatever field has focus.

**Contract (v1):**

| Method | App responsibility | Engine behaviour |
| --- | --- | --- |
| **Start** | Focus the target text field / editable first (so iBus has the right client) | Start listening (same path as toggle-on / panel mic) |
| **Stop** | Optional: keep focus on that field | Commit any leftover partial/preedit, then stop listening (same “commit unfinished then off” idea as typing-interrupt / toggle-off) |

**Transport:** session bus on the existing engine `GApplication` (`org.roojs.ibus-sherpa-onnx` today — already used for `app.open-preferences`). Prefer exported **GAction**s (`Start` / `Stop`, or `Listen` with a boolean) and/or a tiny dedicated D-Bus interface if actions are awkward from non-GLib clients. **💩** Exact names in implementation; document one canonical `gdbus` / Vala / Python snippet in README.

**Sample app flow (documented, not shipped as a second IME):**

1. User clicks the app’s mic button.
2. App `grab_focus()` (or equivalent) on its content / entry.
3. App calls D-Bus **Start**.
4. User speaks; partials/commits appear in that field via iBus as usual.
5. User clicks mic again (or app finishes): app calls D-Bus **Stop** → leftover buffer is committed, mic off.

**Constraints:**

- Sherpa must be the **active** IBus engine (or at least the engine process must be running and able to receive the call — **💩** confirm with Phase A whether Start should also activate/ensure the engine).
- D-Bus does **not** inject text via AT-SPI/ydotool; it only drives listen state. Wrong focus ⇒ text goes to the wrong place (app’s job to focus first).
- **Stop** always attempts to flush the current hypothesis to `commit_text` before clearing listening UI.
- Same listening feedback (badge / preedit / optional notify) as hotkey toggle.
- **🚫** Do not require apps to link against sherpa or ship model paths.

## Phase A — Focus loss & reset handling

### A0 — Signal logging

- **🔷** `⏳` Lifecycle `GLib.debug` on `enable` / `disable` / `focus_in` / `focus_out` / `reset`, plus `focus_in_id` / `focus_out_id` / `set_content_type` when fired (`Engine.debug_lifecycle`). Logs `listening`, `has_focus`, `enabled`, content `purpose`/`hints`, engine id.
- **🔷** Manual matrix: non-editable Alt-Tab; editable-to-editable click; VTE submit; GNOME Text Editor; browser `<input>`.
- **🔷** Write findings into this plan (short “Evidence” subsection) before locking policy.

**How to capture:** engine always writes `GLib.debug` to `~/.cache/ibus-sherpa-onnx/ibus-sherpa-onnx.debug.log` (custom log handler). Add `--debug` on the component `<exec>` (or unpackaged run) for stderr too. After a rebuild/reinstall, `ibus restart` so ibus-daemon respawns the engine, then run the matrix and `tail -f` the log.

### Evidence — Alt window switch (2026-08-10)

Repeated pattern while dictating, then Alt + pick another window:

```
listening ON (has_focus=false)
reset: listening=true …     ← stop happens here
listening OFF (has_focus=false)
focus_out / focus_in …
```

- **Stop cause:** `Engine.reset` (still calls `update_listening(false)` when listening).
- **Not** the key path: no `key ignore (accel while listening)` lines around the stop (WM likely ate Alt+Tab before IME, or the stop is purely reset).
- `focus_out` runs **after** listening is already off.
- `has_focus` / `enabled` often read `false` even while dictating (logging quirk or engine state — do not trust them alone yet).

So A0.5 (ignore accelerators) is still worth keeping, but **A1 must stop treating `reset` as “kill the mic”** for this workflow.

### A0.5 — Ignore WM / accelerator keys while listening (`⏳` coded)

**Hypothesis (likely root cause for Alt+Tab “kills mic”):** while listening, `process_key_event` treated **any** non-toggle key as a typing interrupt. Pure `Alt_L` was ignored, but **Alt+Tab** is `Tab` + `MOD1`, so it stopped the mic before focus/reset even mattered.

**Fix:** if listening and the key has Ctrl / Alt / Super / Meta / Hyper (Shift alone still counts as typing), **do not** stop — `return false` so the WM/app gets the combo. Log `key ignore (accel while listening)`.

Still investigate `reset` / `focus_out` after Alt+Tab; they may also stop listening and need A1.

### A1 — Primary policy

- **🔷** Change `reset` / focus handling so neutral switches do not kill listening when evidence supports it.
- **🔷** Stop + commit-unfinished when entering a new editable context (mirror typing-interrupt behaviour).
- **🔷** Define commit behaviour while unfocused (commit-if-possible vs hold-until-focus_in).

### A2 — Fallback

- **🔷** `block-resets` pref (+ optional hotkey) if A1 is unsafe or incomplete.
- **🔷** When Block Resets on: ignore stop-on-reset; still allow explicit toggle / stop phrase / auto-stop / typing interrupt.

### Phase A success

- **🔷** User ✅: dictate → Alt+Tab / Super / Ctrl+Alt+Left|Right / Ctrl+Tab does **not** stop the mic by itself.
- **🔷** User ✅: typing a letter / Enter still stops listening when that is desired.
- **🔷** User ✅: click into a second text field stops (or documented behaviour); VTE Enter / submit not broken.

## Explicit non-goals

- **🚫** Rewriting the ASR model stack or bundling new weights
- **🚫** Full voice-command language (punctuation dictation suite, “scratch that”, macros) — only paragraph + stop in v1
- **🚫** Fuzzy / LLM command parsing
- **🚫** GNOME Shell extension for focus tracking
- **🚫** AT-SPI / ydotool injection as a substitute for iBus commit (apps use D-Bus for mic state only; text still via iBus)
- **🚫** A full SDK / language bindings package in v1 — documented call samples are enough
- **🚫** Changing the user’s session from the agent without ask
- **🚫** Making Block Resets the default when primary policy can work

## LLM notes

- Implement only after this plan is approved; start with **Phase A logging**, not speculative reset ignores.
- Do not mark backlog **✅**; user verifies after package install.
- Keep silence paragraph vs auto-stop as two thresholds on one clock.
- Voice commands must strip their trigger text; prefer endpoint matches to limit false positives.

- Re-read 0.3 agent rule before any privileged or session command.
