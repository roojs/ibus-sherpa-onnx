## Purpose

🔷 Voice commands use a **suggested phrase prefix** (not a always-on wake word) — OS default from `/etc/os-release` `ID` (`okay ubuntu` / `okay debian` / `okay arch` / …, else `okay linux`), baked into each command’s default full phrase; user can edit.
🔷 Three commands to start: paragraph, line break, stop — each pref is the **full** spoken phrase.
🔷 Prefs UI for those phrases (+ record-to-test control).
🔷 App D-Bus Start/Stop for a host mic button.
🔷 Preferences Test Area (can share the voice-command mic UI).
🔷 WM accelerator keys must not stop the mic by themselves.

ℹ️ Continuous dictation while using other windows = cooperating app keeps a **focused** text field + D-Bus (Phase A conclusion + Phase D). Not an engine `reset` trick.

ℹ️ Silence paragraph / silence auto-stop (old Phase B) — **deferred**; do after voice commands.

## Phase C — Voice commands (suggested phrase prefix)

### Why not bare phrases

🔷 Do **not** match naked “line break” / “new paragraph” alone — those show up in normal / technical speech.
🔷 Each command is a **full phrase** that includes a suggested prefix (same idea as “OK Google …”, but this is just the default wording we ship, not a separate always-listening wake mode).

### Suggested prefix (defaults only)

🔷 On first run, pick a prefix from the OS / distro and **build the three command defaults** with it. User can edit each full phrase afterward; we do not keep re-writing them when the OS string changes.

🔷 Use `GLib.Environment.get_os_info(GLib.OsInfoKey.ID)` → suggested prefix `okay <id>` (e.g. `okay ubuntu`, `okay debian`, `okay fedora`, `okay arch`, `okay linuxmint`). Missing / unusable `ID` → `okay linux`.

ℹ️ Matching: case-insensitive; squeeze spaces; treat spoken `ok` ≈ `okay`.
ℹ️ Examples only — not a fixed whitelist:

| `ID` (examples) | Suggested prefix |
| --- | --- |
| `ubuntu` | `okay ubuntu` |
| `debian` | `okay debian` |
| `fedora` | `okay fedora` |
| `arch` | `okay arch` |
| (missing) | `okay linux` |

### Three command prefs (v1)

🔷 Each preference stores the **entire** spoken phrase (prefix included in the default). Not “one global trigger + fixed tails” unless the UI merely helps fill defaults.

| Pref (action) | Example default (`ID=ubuntu`) | Action when matched |
| --- | --- | --- |
| Paragraph | `okay ubuntu paragraph` | Commit `\n\n`; strip the matched phrase from the text |
| Line break | `okay ubuntu line break` | Commit `\n`; strip matched phrase |
| Stop | `okay ubuntu stop` | Stop listening; strip matched phrase |

Other machines get the same three rows with their `okay <id>` prefix instead.

🔷 Direct stream — no extra ASR buffer beyond normal partial/endpoint.
🔷 Strip the matched phrase so it is not left in the document (brief partial flash OK).

🚫 No LLM / fuzzy semantic matcher in the core path.
🚫 No long command language in v1.

### C1 — RapidFuzz bindings (build-ready)

✔️ Move library VAPIs/shims under `src/vapi/` (sherpa, ICU, RapidFuzz).
✔️ Tiny C++ bridge + `rapidfuzz.vapi`; engine links them so matcher work can call in later.
✔️ RPM `BuildRequires`: `gcc-c++`, `rapidfuzz-devel`.

💩 Alternative (unused): vendored spellfix1.c + sqlite3 for HashCash-identical behaviour.
🚫 Hunspell/Aspell/Enchant; Python fuzzy in-process; homegrown multi-algorithm if-ladder.

### C2 — Config

✔️ `settings.ini` `[general]` keys:

```ini
# example for ID=ubuntu; other distros use okay <id> …
voice-paragraph=okay ubuntu paragraph
voice-line-break=okay ubuntu line break
voice-stop=okay ubuntu stop
```

✔️ Missing keys → fill from OS `ID` prefix + fixed tails (`paragraph` / `line break` / `stop`).
✔️ User edits win; do not reset on later OS detection.

### C3 — Preferences UI

✔️ Two tabs via `Adw.ViewStack` + header `ViewSwitcher`: **General** (listening + model), **Voice commands**.
✔️ Voice phrases use `RowMicText` (`Adw.ActionRow` label + `Gtk.Entry` + mic).
✔️ Mic: refocus entry, synthesize toggle hotkey via AT-SPI (`property_activate` on `current_input_context` did not reach this engine).
✔️ Shared top `Adw.Banner` for engine gate and mic errors (`Preferences.banner()`).
⏳ Engine reloads these strings on `focus_in` / toggle (matcher is C4).
ℹ️ Prefs mic uses AT-SPI hotkey synth for now. Phase D Start/Stop remains for host apps.

### C4 — Matcher (engine)

🔷 Treat an ASR **pause / endpoint** as the check boundary (we already get endpoints from trailing silence). Do **not** fuzzy-scan the whole growing utterance on every partial.

⏳ On each **endpoint** (optional: also on partial for **stop** only if soak wants snappier stop):

1. Normalize the endpoint text (`ok`/`okay`, case, spaces, **strip punctuation** — ASR often yields `okay, ubuntu stop`).
2. Take only the **last ~3–4 words** (longest command is like `okay ubuntu line break` — four tokens). That window is the candidate.
3. RapidFuzz `extractOne` (or ratio) of that window against the three full configured phrases, with a score cutoff.
4. If best ≥ cutoff: strip those last words from the commit text; run paragraph (`\n\n`) / line break (`\n`) / stop.
5. Word-window walk over a long string is **unnecessary** with this design — only needed if we later drop the “last N words” rule.

ℹ️ A command spoken alone → the whole short endpoint *is* those last words.  
ℹ️ A command at the end of a sentence → pause ends the utterance; last N words still catch it.  
ℹ️ A command buried mid-sentence with no pause before/after → may miss; acceptable for v1 (people tend to pause around commands).

### C5 — Done when (user verifies)

- Fresh install defaults use `okay <os-release ID>` (or `okay linux`) in **all three** phrase fields.
- Editing a phrase sticks after restart.
- Speaking each configured phrase does paragraph / line break / stop and does not leave the phrase in the doc.
- Record-in-prefs clears text and starts listening.
