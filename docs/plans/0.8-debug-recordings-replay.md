## Purpose

- **🔷** When enabled, persist each dictated **utterance** as **audio + original text** under a dated cache directory so everyday dictation builds a reusable failure set.
- **🔷** Preferences dialog to **browse** those recordings: pick an item, see the **original text**, hit **Replay through engine**, watch the **output** appear underneath, then (only after that replay) **rate** original and output with stars.
- **🔷** Persist the **secondary output** from a replay (not just show it), and give **that** a 1–5 star rating too — so a five-star original + five-star replay is a strong “tweak held”; five-star original + worse replay output means the tweak regressed.
- **🔷** Stars stay **hidden / disabled until Replay has been run** for the selected item — you can only judge after hearing the clip and seeing Output.
- **🔷** Close the gap where tiny issues are hard to reproduce live — no hand-built test set yet; normal use becomes the set.
- **🚫** In-dialog free-text notes — user keeps prose notes elsewhere (bug files, etc.); stars are the only in-UI annotation.

## Problems to close

| Issue | Notes |
| --- | --- |
| No reproducible audio for bad commits | Live soak only; cannot replay the exact waveform after tweaking prefs/model |
| Original text vs replay output not side-by-side | Hard to tell what went wrong without hearing the clip and seeing what the engine produces now |
| No signal that a clip / replay was “known good” | After tweaking prefs, need light quality marks on both the original pass and the replayed Output |
| No lightweight review UI | CLI `--script` exists for *expected* lines + mic; not for *recorded* failures |
| Cache already used for downloads / debug log | Need a **dedicated** dated tree, not mixed into download staging |

## Desired UX

1. Open Preferences → **Debug** tab → turn on **Save debug recordings** (Browse row appears) → Close (engine picks up on next `focus_in` / listen as today).
2. Dictate normally. Each committed utterance writes a pair under today’s date folder.
3. Later: Preferences → **Debug** → **Browse…** opens a dialog:
   - **Left:** list of scanned items — **newest first**; row shows weekday + 12-hour time + first line of original text.
   - **Right, top → bottom:**
     1. **Original text** (read-only)
     2. **Replay through engine**
     3. **Output** — text appears here as the recording is replayed; when Replay finishes, that text is **saved** beside the recording
     4. **Stars** (only after Replay has completed for this selection) — rate the **original**, and rate **this output**
4. Workflow: Replay → hear + watch Output → rate both. Later tweak prefs → Replay again → new Output overwrites the saved secondary text → re-rate the output (and keep/compare against a five-star original).

```
┌─────────────┬──────────────────────────────────────────┐
│  list of    │  Original text                           │
│  items      │  ─────────────────────────────────────── │
│  (left)     │  [ Replay through engine ]               │
│             │  ─────────────────────────────────────── │
│             │  Output                                  │
│             │  ─────────────────────────────────────── │
│             │  Original  ★ ★ ★ ★ ★                     │
│             │  Output    ★ ★ ★ ★ ★                     │
└─────────────┴──────────────────────────────────────────┘
```

**Replay through engine** (one button):

1. Plays the recording so you can hear it.
2. Runs that same audio through the engine and fills **Output** underneath as recognition proceeds (text updates while it plays — like live dictation, not a dump at the end).
3. On finish: **write** the Output text to disk; **reveal** the star rows at the bottom (if this was the first Replay for the selection, or always keep them visible once unlocked for this visit).

**🚫** Do not show star controls before the user has Replay’d — rating without hearing is useless.

**Stars = human reference quality**, not an auto score:

| Control | Typical use |
| --- | --- |
| Original ★★★★★ | Live capture text was right — strong regression reference |
| Output ★★★★★ | This Replay result was also right — tweak held (or baseline re-check passed) |
| Output ★☆☆☆☆ | Replay got worse — tweak looks bad vs a good original |
| (unset) | Not judged yet (or stars still locked until Replay) |

Stars never auto-change. Re-Replay replaces saved Output text; user re-rates Output as needed. Original rating usually stays unless they change their mind about the capture.

## On-disk layout

```
~/.cache/ibus-sherpa-onnx/debug/
  YYYY-MM-DD/
    HHMMSS.txt              # original committed text (UTF-8)
    HHMMSS.wav              # mono 16 kHz PCM (see Format)
    HHMMSS.rating           # optional: 1–5 for original; absent = unrated
    HHMMSS.out.txt          # last Replay Output text (written when Replay finishes)
    HHMMSS.out.rating       # optional: 1–5 for that Output; absent = unrated
```

- **🔷** One **utterance** = one basename shared by `.txt` / `.wav` / optional rating + output sidecars — not one giant session file.
- **🔷** Date folder = local calendar day when the utterance was committed (`YYYY-MM-DD`).
- **🔷** Basename = wall **`HHMMSS`** — two endpoint commits in the same second are not realistic for spoken utterances.
- **🔷** Save only when there is real committed text (same path as today’s endpoint commit). No empty clips.
- **🚫** Do not write into `~/.config/`; cache only. **🚫** Do not mix with `~/.cache/ibus-sherpa-onnx/download/`.
- **🚫** No `.notes` or settings snapshot (`.meta.ini`) — we do not yet know which knobs matter; Replay always uses whatever prefs/model are current.
- **🔷** `.rating` / `.out.rating` are user judgment only (browse dialog). Engine at capture time writes only `.txt` + `.wav`.
- **🔷** Each finished Replay **overwrites** `.out.txt` (latest secondary output only — 💩 no history of every Replay unless we need it later). Clearing Output rating on overwrite is fine (**💩** or keep old `.out.rating` until user changes it — prefer **clear** so a stale five-star does not lie about new text).
- **ℹ️** **Files first, not SQL.** Sidecar layout is enough to start reviewing. A later pass can **import** this tree into SQLite (or similar) if browsing/filtering gets painful — do **not** build a DB schema in 0.8.
- **🚫** No SQLite / other DB in this slice.
- **🚫** Auto-prune / retention knobs — turn the pref off when not capturing; delete folders by hand if needed.

### Audio format

Mic path today is already **F32LE mono 16 kHz** ([`Transcriber`](../../src/Transcriber.vala) appsink). For recordings:

- **🔷** Prefer a **standard `.wav`** (PCM 16-bit or float — pick one and stick to it) so GStreamer playback and external tools work.
- **🔷** Persist the **same samples** fed to `accept_waveform` for that utterance (from segment start → endpoint), not a second capture path.
- **💩** Float WAV vs S16LE: S16LE is more portable for speakers; float matches the recognizer input exactly. Prefer **S16LE WAV** for playback + convert back to float on Replay, unless conversion noise shows up in comparisons — then switch to float WAV.

## Design

### Recording (engine path)

- **🔷** Pref `general/debug-recordings` (default `false`). Preferences **Debug** tab: enable switch; when on, show a **Browse…** row (hidden when off).
- **🔷** When on: buffer PCM for the current segment in `Transcriber` (or a thin helper owned by Engine). On successful **endpoint commit**, write `.wav` + `.txt` under today’s folder; create parents `0755`.
- **🔷** Text content = the string actually committed (post any Engine formatting that already ran — so the recording matches what the user saw).
- **ℹ️** If 0.6 later inserts `\n\n` / strips voice commands before commit, save **post-policy** text.
- **🚫** Do not block the audio worker on disk I/O — write on Idle / a short async write after commit.

### Replay (prefs process)

- **🔷** Dialog lives in `ibus-setup-sherpa-onnx` (same pattern as Preferences / future Test Area): in-process `Transcriber` loaded from the active `model` symlink + language (whatever is selected now — no snapshot of old settings).
- **🔷** **Replay through engine** (single action):
  - Play the `.wav` on the speakers (ignore `mute-speakers`).
  - Feed the same audio into the recognizer (**no mic**); update **Output** as text arrives (**💩** pace with playback so eye tracks ear).
  - On finish: write `.out.txt`; unlock / show star rows at the bottom; clear previous `.out.rating` when Output text changes.
- **🔷** File-feed API on `Transcriber` (push WAV samples without `autoaudiosrc`). Mic path unchanged for live dictation.
- **🚫** Replay must **not** write a new `.wav` / original `.txt` (secondary output only).
- **🚫** No separate Play-only control — Replay is hear + fill Output.

### Browse dialog

- **🔷** Scan `debug/` date folders + `*.txt` (not `*.out.txt`); list **newest first** (day folders reverse, then time reverse).
- **🔷** List row label: **weekday** (e.g. Wednesday) + **12-hour time** (e.g. 1:05 PM) + **first line** of the original `.txt`.
- **🔷** Selecting a row loads **Original text**; loads saved **Output** / ratings if present; enables Replay. **Star rows stay hidden** until Replay completes in this session (prefer **hidden until Replay** so judgment always follows hearing).
- **🔷** After Replay: show two star controls at the **bottom** — **Original** → `.rating`, **Output** → `.out.rating`. Write immediately on click.
- **🔷** Entry point: **Debug** tab → **Browse…** (only visible while save is enabled).
- **💩** Star widget choice; whether list shows both ratings.
