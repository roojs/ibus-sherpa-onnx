## How much Transcriber changes

Sherpa already unifies backends behind one C API. Our VAPI already has `OnlineParaformerModelConfig`. The mic → queue → Idle path does **not** need a second class.

| Area | Nemotron today | Paraformer | Change size |
| --- | --- | --- | --- |
| GStreamer mic + `AsyncQueue` + worker + Idle | Yes | Same | **None** |
| `accept_waveform` / `is_ready` / `decode` / `get_result` / `is_endpoint` / `reset` | Yes | Same | **None** |
| `Engine` / prefs download / `model` symlink | Pack id | Pack id | Catalog only |
| `OnlineRecognizerConfig.model_config` | `transducer` encoder+decoder+joiner | `paraformer` encoder+decoder | **`load()` only** |
| `stream.set_option("language", …)` | Nemotron locale hint | Not used (no prompt dictionary) | Skip when arch ≠ nemotron |
| `blank_penalty` / timestamps | Used | No timestamps; blank_penalty often 0 | Small config tweaks |
| Optional `set_option("is_final", …)` | Unused | Documented for Paraformer | 💩 only if endpoint quality needs it |

**Estimate:** ~30–80 lines in `Transcriber.load()` (+ tiny catalog reads). Not a rewrite. Decode loop stays.

### Architecture choice (do this)

**Prefer: one `Transcriber` + catalog-driven config builder. No ASR base-class hierarchy.**

```
languages.ini  family=…  (+ optional stream=)
models.ini     family=…  arch=transducer|paraformer  (+ paths if needed)
                    │
                    ▼
            Transcriber.load()
              builds OnlineRecognizerConfig
              from arch + model_dir
                    │
                    ▼
         same processing_loop() as today
```

- **🔷** Add `arch=` on pack rows in [`resources/models.ini`](../../resources/models.ini) (`transducer` default for existing Nemotron; `paraformer` for the trilingual pack).
- **🔷** `load()` switches which sub-struct is filled; leave the other empty.
- **🚫** Do **not** invent `TranscriberBase` / `NemotronTranscriber` / `ParaformerTranscriber` for this. Inheritance would duplicate mic/queue/Idle for a config fork.
- **💩** If a future backend cannot use `OnlineRecognizer` at all (true offline-only), then introduce a thin `AsrBackend` interface — not now.

Secondary “transformer” in the ML sense (another model) = **another catalog family/pack**, still loaded by the same `Transcriber`.

## Catalog / prefs (small)

- **🔷** New pack family e.g. `paraformer-zh-yue-en` with one (or two) chunk-less / single-size rows — Paraformer packs are not Nemotron 560/1120 trees; ship the int8 trilingual archive as one pack id.
- **🔷** New language row(s), e.g. `yue-HK` (or `yue`):
  - `family=paraformer-zh-yue-en`
  - `stream=` empty (no Nemotron language option)
  - `label=` / `display=` for 粵語 / Cantonese (same ICU/`label=` pattern as Mandarin)
- **🔷** Keep `zh-CN` on `nemotron-3.5-ml` (better Mandarin story). Do not force Mandarin onto Paraformer unless we want one pack for both later.
- **🔷** IBus engine id + component `<language>` for the new prefs code (same Phase B pattern as 0.5).
- **🔷** Download/install unchanged (URL + digest from GitHub Releases API).

**🚫** Pretend Nemotron can do Cantonese via `stream=yue`.

## Implementation phases

### Phase A — Paraformer load path (engine)

1. **🔷** `arch=` in `models.ini`; default missing → `transducer`.
2. **🔷** `Transcriber.load()`: fill `paraformer` **or** `transducer`; skip `set_option("language")` when arch is paraformer (or when `stream=` empty — already close).
3. **🔷** CLI smoke: mic or file decode with the trilingual pack.
4. **🔷** User ✅: Cantonese utterance → sensible 粤语 text with Paraformer pack selected.

### Phase B — Prefs catalog

1. **🔷** Pack + `yue-HK` (name 💩) language row; engine XML entry.
2. **🔷** User ✅: Preferences → Cantonese → download Paraformer → dictate.
