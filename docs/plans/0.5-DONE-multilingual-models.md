## Desired UX

1. Open Preferences.
2. Choose **Language** (e.g. English, Japanese, ...).
3. **Select model** list updates (chunk sizes / pack family available for that language; **installed** / **needs downloading** as today).
4. Close → pipeline runs → GNOME has Sherpa → IBus restarted → dictate in that language.

Default language: **desktop UI locale** on first setup (see below). Default model selection: **None** until the user picks (unchanged).

### Language combo labels (no in-repo reference UI)

There is **no** existing language-selector widget in this repo (or a known RooTerm/OLLMchat reference to copy). Prefer the usual desktop pattern:

**Endonym (native script) + name in the system UI language.**

Examples on an English desktop:

| Code | Combo row |
| --- | --- |
| `ja` | `日本語 — Japanese` |
| `de` | `Deutsch — German` |
| `zh-Hans` / `zh-CN` | `中文（简体） — Chinese (Simplified)` |
| `zh-Hant` / `zh-TW` | `中文（繁體） — Chinese (Traditional)` |
| `en` | `English` (same twice → show once) |

Rules:

- **Native first** so speakers recognise their language immediately (CJK characters included).
- **System-language second** so anyone who cannot read that script can still pick the right row.
- **Chinese:** two curated entries (Simplified vs Traditional), both with Chinese characters in the endonym; do not collapse to a single “Chinese”.
- If endonym equals the system-language name, show one string only.
- **🚫** Hard-code English glosses for every row when the UI is German/Japanese/etc.; the second part follows the session locale.

**Spoken Chinese ≠ written Chinese.** ISO 639 lists spoken varieties (`cmn` Mandarin, `yue` Cantonese, ...) separately from script variants **Hans / Hant** (ISO 15924). Prefs language rows for ASR follow **BCP-47 / CLDR-style tags** (`zh-Hans`, `zh-Hant`, ...) — a bit of a category mash, but that is how locale UIs and the model’s language option are usually keyed. Do not pretend Hans/Hant are “dialects.”

### Label source: ICU (Phase A)

**Use ICU for combo labels.** Call `uloc_getDisplayName` via slim `src/icu-i18n.vapi` (no C helper):

- endonym = display name of our tag **in that language’s own locale** (`ja` → `日本語`, `zh_Hans` → `中文（简体）`)
- gloss = display name of the same tag **in the session UI locale** (`GLib.get_language_names()[0]` → e.g. English `Japanese` / `Chinese (Simplified)`)
- join with ` — `; if equal, one string only

Verified on ICU 76: `zh_Hans` / `zh_Hant` work; bare `ja` / `de` work.

**Packaging (prefs binary only — engine does not need this):**

| Distro | Build | Runtime (pulled by shlibs, or declare) |
| --- | --- | --- |
| Debian/Ubuntu | `libicu-dev` | `libicu76` (SONAME follows distro) |
| Fedora | `libicu-devel` | `libicu` |

Meson: `dependency('icu-i18n')` on `ibus-setup-sherpa-onnx` (not the IBus engine). Debian `Build-Depends` + RPM `BuildRequires` accordingly; `${shlibs:Depends}` / automatic RPM deps should pull the runtime lib.

Labels via `Icu.display_name()` (`src/Icu.vala` + `icu-i18n.vapi` stub); curated **codes** stay in `resources/languages.ini`.

### What is `iso-codes`? (not our primary path)

**`iso-codes` is a data package**, not a library you link:

- Debian/Ubuntu/Fedora package name: **`iso-codes`** (Architecture: all)
- Ships JSON under `/usr/share/iso-codes/json/` (ISO 639 languages, 3166 countries, **15924 scripts**, ...) and gettext `.mo` files (`iso_639-3`, `iso_15924`, ...) under `/usr/share/locale/*/LC_MESSAGES/`
- Apps look up English msgid → translated name via gettext; optional CLI `isoquery` is a separate tiny package
- GNOME Region & Language **Recommends** it; it does **not** replace ICU for `zh-Hans`-style locale display names

**Phase A: do not Depend on `iso-codes`.** ICU’s CLDR data lives inside `libicudata` — localized names work without the `iso-codes` package. (`iso-codes` is only needed if you look up names via its gettext domains / JSON; without that package those lookups fall back to English msgids.) IBus `get_language_name` alone is too weak for Hans/Hant.

### Default language from the UI

The person setting up the machine has usually already chosen their desktop language (GNOME Region & Language → session `LANG` / `LANGUAGE`). Prefer that over hard-coding English.

- **First run** (no `general/language` in `settings.ini` yet): call `GLib.get_language_names()`, map the first supported tag (`ja`, `de`, ...) into our curated list; if nothing matches → **`en`**.
- **After that:** persist `general/language=` and **leave it**. Do not keep re-syncing when the desktop language changes. The user may later switch to English (or anything else) in Preferences on purpose.
## Design choices

### Phase A in one sentence

Preferences: **Language** select → rebuild **Select model** list for that language; on first load default language from the desktop UI. Catalog data is a **fixed GResource** (KeyFile). The engine only reads `general/language=` from `settings.ini` for `set_option` — it does **not** load the catalog.

### Catalog as GResource (prefs / Models only)

Ship KeyFiles from **`resources/`** (not `data/`) → `GResource`. Split so languages and packs stay readable:

| File | Role |
| --- | --- |
| [`resources/languages.ini`](../../resources/languages.ini) | One group per language (file order = combo order); `stream=` / `tier=` / `family=` |
| [`resources/models.ini`](../../resources/models.ini) | Packs keyed by short id (`nemo-en-560`); per block: `name=`, `url=`, `archive_bytes=` (format UI size from bytes; no `[catalog]` / no `size=`) |

Join: language.`family` == model.`family`. (`data/` stays installable bits: component XML, polkit, desktop — **not** checksum digests.) Review both files before wiring.

[`Models.vala`](../../src/Models.vala) will parse the GResource into the catalog used by Preferences (filter by language, download URLs). Archive integrity comes from the **GitHub Releases API** `digest` at download time, not packaged sidecars.

Prefs:

- **Language** row → writes `general/language=` in user `settings.ini` (sticky after first default from UI locale).
- Changing Language → refresh **Select model** (only packs that serve that language); clear model selection if the current symlink no longer fits.
- **English** → Family A packs only (v1). **Other locales** → Family B only.

### Runtime (Transcriber) — no catalog

- User `settings.ini` already loaded by the engine via [`Config`](../../src/Config.vala) (hotkey etc.). Add `general/language=`.
- After `create_stream` (and after `reset` if needed): if language is not English-only,  
  `stream.set_option("language", value)` (VAPI bind `SherpaOnnxOnlineStreamSetOption`).
- English-only active model: skip `set_option` (option ignored by that pack anyway).
- **🚫** Engine does **not** open the catalog GResource / resource inis. It only needs the language string the model should use.

### GNOME / IBus language presentation

Two layers — keep them honest:

| Layer | What it means |
| --- | --- |
| ASR language | Prefs `language` + model family + stream option |
| Settings grouping | Component `<language>` / `<layout>` (and which engine id is in `input-sources`) |

**Recommended for 0.5:**

1. **Phase A (ASR + prefs catalog)** — Language + filtered models + download/install + stream hint. Keep a **single** engine id `sherpa-onnx` in gsettings (0.4 `ensure_input_source`). Accept that GNOME may still group the IME under English until Phase B.
2. **Phase B (Settings grouping)** — Map prefs language → IBus `<language>` + `<layout>` so Settings shows the IME under the right language:
   - **Option B1 (preferred):** multiple `<engine>` entries in `sherpa-onnx.xml` sharing the same binary (`sherpa-onnx-en`, `sherpa-onnx-ja`, ...) with fixed language/layout; prefs switches the gsettings source to the matching engine name (still one process pattern via factory).
   - **Option B2:** single engine; only update longname/description; grouping stays weak.

**🚫** Do not rewrite system component XML from prefs. **🚫** Do not invent a second parallel IME package per language.

Layout map (starter; expand with catalog): `en`→`us`, `ja`→`jp`, `de`→`de`, ....

### Install / finish path

Reuse 0.4 finish:

1. User download + libarchive extract → `~/.cache/ibus-sherpa-onnx/download/`.
2. `pkexec` install-model (allowlist **must** grow for new dir names).
3. User `model` symlink → system tree.
4. `ensure_input_source` (engine id from Phase B map if multi-engine).
5. `ibus restart` + close.

CLI: extend `cli-fetch-nemotron-model.sh` with language + chunk, or `--list` / args mirroring prefs (**⏳** after prefs path works).

### Config

```ini

hotkey=Ctrl+Shift+Space
notifications=false
```

Active weights remain the **`model` symlink** (not a path in the ini). Language is orthogonal so switching language can imply a different default model / require re-pick if the current symlink’s family does not support the new language (clear selection to None or prompt — prefer **auto-clear model radio to None** when language change invalidates current symlink).

## Phase A — Prefs language + multilingual ASR

### A0 — Catalog (`✔️`)

Plain meaning of the ini fields (not a separate work item):

- **`family=`** — same string on a language and on a model pack so prefs know which downloads to show (English → `nemotron-en` packs; Japanese etc. → `nemotron-3.5-ml` packs).
- **`stream=`** — string the runtime later sends as the model’s spoken-language hint (`ja-JP`, ...). Empty for English-only packs.

**Checksums — fetch from upstream, do not ship in our package:**

- **🚫** No digests in `resources/*.ini`.
- **🚫** Stop shipping `data/checksums/*.sha256` in the `.deb`/`.rpm` (remove the 0.4 sidecars once download verifies via API).
- **Source of truth:** GitHub Releases API for tag `asr-models`. Each asset already exposes `digest` (`sha256:...`) and `size` — confirmed for our en + multilingual Nemotron archives; matches the old packaged en-560 digest.
- **Download flow:** resolve asset metadata (digest + size) from the API → download `url` from `models.ini` → SHA-256 verify against API digest → extract. No digest / mismatch ⇒ fail closed.
- Cache the fetched digest in the extracted tree’s `.sha256` stamp (local only) so `Models.ready` can still compare without re-hitting the API every engine start — or revalidate against API only at download time and treat a present stamp + required files as ready (**💩** pick at A1; prefer stamp written at successful download).

- **🔷** Later (download wiring): verify via GitHub asset `digest`; drop packaged `data/checksums/`; polkit allowlist still needs the new multilingual dir `name=` values.
